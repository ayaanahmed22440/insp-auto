# Admin system brief summary

The requested feature is a private, production-ready admin panel for the INSP AUTO vehicle-history platform, not a public marketing page. It must use secure server-enforced authentication: email/password, cryptographically random six-digit single-use email OTP, server-side password hashing with scrypt or Argon2id, OTP peppering, expiry, attempt limits, rate limits, secure HttpOnly Secure SameSite cookies, hashed sessions, revocation, CSRF/origin protections, generic auth errors, and no tokens or secrets in browser storage.

Admin authorization must be enforced server-side on every admin endpoint. Public contact, FAQ, pricing, and order-status flows must remain separate. The dashboard must use the supplied dark navy/electric-blue INSP AUTO branding, existing logo, persistent desktop sidebar, mobile drawer, admin identity, logout, breadcrumbs, loading/empty/error states, visible focus, and responsive layouts.

Persistent database-backed features required: dashboard counts from real records; searchable/filterable/sortable/paginated contacts with statuses new/read/in_progress/replied/resolved, notes, delete confirmation, and audit logs; paid-order fulfillment queue with separate payment and fulfillment statuses; verified/idempotent payment webhooks; customer order ownership checks; audit logging; secure headers, validation, escaping, rate limits, safe CORS/origin checks, and monitoring.

Public contact submissions must validate strictly, persist before notification, notify the configured administrator mailbox with Reply-To, and remain saved if email delivery fails. No fake customers, reviews, payments, metrics, seeded demo data, hardcoded credentials, or mock security are allowed. Secrets must be server-only environment variables with a secret-free example; tests must cover authentication, OTP, sessions, authorization, CSRF/origin, contact persistence, email failure, webhooks, ownership, XSS safety, and rate limiting. Existing public website design, payment links, deployment configuration, and unrelated functionality must be preserved.
